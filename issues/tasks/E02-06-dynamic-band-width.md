# E02-06: 帯幅を今のモードに合わせる

親: [E02: パフォーマンス改善](../epics/E02-performance.md)

## 概要

帯幅は全モードの `Thick + BlurMax` の最大(手元の設定で132px)で固定されている。Focus(12px で足りる)でも132px 分を毎フレーム描いている。帯幅を「今のモードとフェード先のモード」の最大に合わせ、モードが変わるときにウィンドウをリサイズする。

## 完了条件

- Focus の間は帯幅が Focus の太さ+ぼかしに合わせて細くなっている
- フェード中に見た目が欠けない(フェードが始まる前に帯を広げる)
- `tools/measure.ps1 -Mode Focus` で負荷が下がっていることを確かめる

## 依存関係

E02-02 の後。E02-04・E02-05 とは独立

## 設計の決定

- 帯幅は `EdgeBandLayout.CalculateBandWidth(PomodoroState, TransitionSec)` で決める。今のモードの「太さ + ぼかしの最大」に、フェードが近いとき(残り `TransitionSec` + 2秒以内、またはフェード中)だけフェード先のモードを加える。常に加えると Focus 中も Rest の幅が要って細くならないため
- 強制・スケジュール時は Current と Target が同じなので、そのモードの幅になる
- 帯幅は毎フレーム計算するが、ウィンドウの配置し直しは値が変わったときだけ(1サイクルに数回)。スケジュールで即座に切り替わる場合も、そのフレームで先に帯を広げてから描く
- 全モードの最大で帯幅を決めていた旧 `CalculateBandWidth(AppConfig)` は削除した

## 検証結果

2026-09-29

- 見た目:黒背景で E02-01 時点のビルドと比べ、太さ2・ぼかし10(帯幅14px)、太さ20・ぼかし40 のどちらもピクセル単位で一致した(差0)
- 負荷(デバッグ表示あり、30FPS、1コア換算)

| モード | 帯幅 | E02-05 CPU | E02-06 CPU | E02-06 GPU | DWM CPU / GPU |
|------|------:|------:|------:|------:|------:|
| Focus | 14px | 29.0〜29.4% | 19.9〜20.2% | 6.0% | 12.5% / 2.4% |
| Rest | 102px | 27.4〜28.8% | 23.9〜25.4% | 17.6〜19.1% | 13.8% / 3.5% |
| Sleep | 132px | — | 26.0〜28.5% | 17% | 13.4% / 6.0% |

- テスト75件すべて成功

## 未検証のまま残したこと

- フェードの前後で帯が実際に広がり・縮むこと、そのときにちらつかないことは、アプリ上で確かめていない(ロジックはユニットテスト済み)
- Focus で帯の面積は約1/9になったが、CPU は約2/3までしか下がらない。帯の面積によらない固定費がありそう。候補はウィンドウ枚数ごとの転送処理、デバッグ表示のウィンドウ、モニター全体サイズの `Rectangle` にかかる `BlurEffect` だが、内訳は切り分けていない
