# E02-04: デバッグ表示の更新を間引く

親: [E02: パフォーマンス改善](../epics/E02-performance.md)

## 概要

デバッグ表示は毎フレーム(16msごと)大きなテキストを組み直していて、それだけで約17%(1コア換算)を使っている。初期状態でスクリーン1に出ているので影響が大きい。テキストの更新を1秒に数回に減らす。

## 完了条件

- デバッグ表示のテキスト更新が毎フレームではなくなっている
- `tools/measure.ps1` で、デバッグ表示ありの負荷が下がっていることを確かめる

## 依存関係

E02-03 の切り分け結果による。他のタスクとは独立

## 設計の決定

- テキストの組み立てと表示は250msごと(1秒に4回)にした。表示内容は秒単位の残り時間・進捗・物理量なので、これで足りる
- FPS 表示はフレーム間隔の平均から出しているので、間隔の記録(`DebugManager.RecordFrame`)だけは毎フレーム続ける。`GenerateDebugText` から delta の引数を外した
- デバッグ表示が非表示のときは、記録も組み立てもしない(従来どおり)

## 検証結果

2026-09-29、Rest 固定、デバッグ表示あり(初期状態)

| 計測 | PomOverlay CPU | DWM CPU |
|------|------:|------:|
| E02-02(毎フレーム更新) | 49.1% | 16.8% |
| E02-04 1回目 | 35.7% | 18.4% |
| E02-04 2回目 | 32.6% | 16.9% |

- デバッグ表示なしの実験値(34%)と同じ水準になった。デバッグ表示のコストはほぼ無くなった
- テスト55件すべて成功

## 未検証のまま残したこと

- デバッグ表示の見た目(1秒に4回の更新で、スピナーや数字の動きが不自然でないか)は本人の目で確認していない
