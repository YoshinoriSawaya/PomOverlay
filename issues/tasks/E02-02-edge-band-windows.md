# E02-02: ウィンドウを画面の縁の帯だけにする

親: [E02: パフォーマンス改善](../epics/E02-performance.md)

## 概要

今は各モニターに全画面サイズのレイヤードウィンドウを置いている。`AllowsTransparency` はソフトウェア描画になるため、縁しか光らせていなくても画面全体を毎フレーム転送している。`Modes` 内の `BlurMax`/`Thick` の最大値から逆算した幅の帯だけをウィンドウにする。帯幅は設定の変更時にだけ計算し直す。

## 完了条件

- 各モニターのオーバーレイが、縁の帯だけのウィンドウで構成されている
- 見た目が今と大きく変わらない(手動確認)
- E02-01 の手順で計測して、改善前より負荷が下がっている

## 依存関係

E02-01 の後。

## 設計の決定

- 1モニターあたり上・下・左・右の4枚の帯ウィンドウ(`EdgeBandWindow`)にした。各ウィンドウには今までと同じモニター全体サイズの `Rectangle` を座標をずらして置き、自分の帯に当たる部分だけを見せる。グラデーション(`RelativeTransform` がモニター全体基準)と角のぼかしのつながりを、描き方を変えずに保つため
- 帯幅は `EdgeBandLayout.CalculateBandWidth`:全モードの `Thick + BlurMax` の最大値を切り上げ、余白2pxを足す。フェード中は Thick と Blur が同じ比率で補間されるので、合計がこの最大値を超えることはない。設定が変わったとき(`UpdateConfig`)だけ計算し直す
- 帯がモニターの短辺の半分以上になる場合は、全画面ウィンドウ1枚に戻す
- `MainWindow` を廃止し、1モニター分の配線を `MonitorOverlay`(Window ではない普通のクラス)に移した。タイマー・`AuroraPhysicsCalculator`・`ConsecutiveFailureLimiter` は1モニターに1つ
- グラデーションの色の計算は `GradientColors.Calculate` に切り出し、1フレームに1回だけ計算して4枚に配る
- デバッグ表示は小さな専用ウィンドウ(`DebugWindow`、`SizeToContent`)に分けた。位置は今までと同じモニター左上から20px
- クリック透過の P/Invoke は `ClickThrough.Apply` にまとめ、帯ウィンドウとデバッグウィンドウで共有する
- 座標は今までどおり `Screen.Bounds` をそのまま WPF の座標として使っている(DPI の扱いは変えていない)

## 検証結果

- 2026-09-29: テスト55件すべて成功(`EdgeBandLayout` のテスト6件を追加)
- 見た目:旧版と新版を Rest 固定で起動してスクリーンショットを比べ、四辺と角のオーロラが同じように出ていること、帯の継ぎ目が見えないことを確かめた(Claude が確認。スクリーンショットは確認後に削除)
- 計測:`tools/measure.ps1` に `-Mode`(モード固定)を追加し、旧版(13654c3)と新版を同じ条件で計測した。手元の `config.json` での帯幅は132px

| 項目 | 旧 Sleep | 新 Sleep | 旧 Rest | 新 Rest |
|------|------:|------:|------:|------:|
| PomOverlay CPU(1コア換算) | 59.2% | 47.4% | 49.1% | 49.1% |
| PomOverlay GPU(3D) | 29.6% | 18.6% | 34.2% | 23.8% |
| DWM CPU 起動中(起動前) | 24.4%(1.9%) | 16.4%(3.2%) | 21.6%(2.4%) | 16.8%(5.7%) |
| DWM GPU(3D) | 12.0% | 4.4% | 11.2% | 4.0% |
| PomOverlay WorkingSet / Private | 202 / 556 MB | 155 / 312 MB | 202 / 442 MB | 154 / 306 MB |

- 転送と合成の負荷(DWM の CPU・GPU、PomOverlay の GPU、メモリ)ははっきり下がった
- PomOverlay 自身の CPU はほぼ変わらない。モニター全体サイズの `Rectangle` に毎フレームかけている `BlurEffect`(ソフトウェア描画)が CPU の大半を占めていると考えられる。これは E02-03 で取り除く
- デバッグ表示の FPS は新旧とも約40(タイマーは16ms 間隔だが描画が追いついていない)

## 未検証のまま残したこと

- 本人の目での見た目の確認(フェード中、Focus の細い線、デバッグ表示の位置)
- 帯が全画面1枚に戻るケース(帯幅が短辺の半分以上)と、設定リロードで帯幅が変わるケースの実機確認
- Windows の表示スケールが100%以外のモニターでの位置(従来から DPI を考慮していない。今回も同じ扱い)
- 各帯ウィンドウがモニター全体サイズの要素を持つため、`BlurEffect` の計算が4枚それぞれで起きている可能性がある。E02-03 でぼかしを事前ベイクすれば解消する
