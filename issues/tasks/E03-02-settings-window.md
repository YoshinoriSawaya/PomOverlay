# E03-02: 設定ウィンドウとトレイメニュー

親: [E03: 設定ウィンドウ](../epics/E03-settings-window.md)

## 概要

E03-01 の ViewModel に結びつく WPF の設定ウィンドウを作り、トレイメニューから開けるようにする。「適用」で `config.json` に保存し、全モニターのオーバーレイに反映する。

## 完了条件

- トレイメニューの「設定...」で設定ウィンドウが開く(すでに開いていれば前面に出す)
- 「適用」で保存と反映が行われ、不正な値があれば一覧を表示して適用しない
- 見た目の確認(手動)

## 依存関係

E03-01 の後

## 設計の決定

- `Views/SettingsWindow.xaml`:タブは「全般」(`TransitionSec`・`Fps`)、「モード」(Focus/Rest/Sleep をさらにタブで切り替え)、「スケジュール」(表で一覧し、追加・削除)。下部に「適用」「閉じる」と状態の表示
- コードビハインドは配線だけ。「適用」では、数値として読めない入力(WPF のバインディングエラー)を先に止め、次に `SettingsViewModel.TryBuildConfig` の結果で、理由の一覧を出すか適用するかを決める
- トレイメニューの「設定操作系」の先頭に「設定...」を追加した。すでに開いていれば前面に出す(1つだけ)
- 適用は `App.ApplySettings`:`config.json` に保存し、全モニターに反映する。`OverrideMode` はウィンドウを開いている間にトレイから変わりうるので、適用の時点の値を引き継ぐ
- 設定ウィンドウでは、`ConfigValidator` の文言のうち補正の内容(「30 を使います」など)は紛らわしいので出さない。そのため `ConfigValidator.Sanitize` の戻り値を `ConfigIssue(Problem, Fix)` に変えた。起動時のダイアログは従来どおり両方を表示する
- 「閉じる」は未適用の変更を確認せずに捨てる

## 検証結果

2026-09-30

- テスト83件すべて成功
- 起動時に設定ウィンドウを開く実験用ビルド(コミットしない)で、UI オートメーションを使って確かめた。操作したのは実験用フォルダの `config.json` で、手元の設定には触れていない
  - 3つのタブが手元の設定値(Focus 15分など)で表示される(スクリーンショットは設定ウィンドウの範囲だけ撮り、確認後に削除)
  - FPS に `abc` → 「赤枠の欄に数値として読めない入力があります」と出て、保存されない
  - FPS に `500` → 「次の値を直してから適用してください。Fps は1～60で指定してください (500)」のダイアログが出て、保存されない
  - FPS に `20` → 「適用しました」と出て、`config.json` の `Fps` が20になる。モード名は `"Sleep"` のように名前で保存される

## 未検証のまま残したこと

- トレイメニューから実際に開く操作(実験では起動時に開いた)と、適用後にオーバーレイの見た目が変わることは、本人の目で確かめていない
- 数値として読めない入力のチェックは、今見えているタブの欄しか見ていない。赤枠のまま別のタブに移ってから適用すると、その欄は直前の正しい値のまま適用される
- 表示スケールが100%以外の環境での見た目
