# E02: パフォーマンス改善

## 概要

常駐ツールとして重さが気になる状態を改善する。効果を判断できるよう、最初に今の重さを計測しておく。

当初は全画面のレイヤードウィンドウと毎フレームの `BlurEffect` を対象にしていたが、E02-03 の切り分けで、負荷の主因は「毎フレーム再描画・転送するピクセル数 × フレームレート」だと分かった(`BlurEffect` は主因ではなかった)。そこで E02-04〜06 で、デバッグ表示・フレームレート・帯幅を減らす。

## 完了条件

- E02-01 と同じ手順で計測して、CPU 使用率が下がっていることを数値で確かめられている
- 見た目(フチの色・ぼかし・明滅・流れ)が大きく変わっていない(手動確認)

## 依存関係

E01 の完了後。E02-01 を最初に行う。E02-04・E02-05・E02-06 は互いに独立。

## 結果のまとめ(2026-09-29)

| モード | E02-01 時点 | E02-06 後 |
|------|------:|------:|
| Focus | —(Sleep/Rest と同程度) | 約20% |
| Rest | 49.1% | 約25% |
| Sleep | 49〜59% | 約27% |

(PomOverlay の CPU、1コア換算。DWM の CPU は約23% → 約13%、GPU の合計は約40% → 10〜25%)

完了条件のうち、数値での改善は確かめた。見た目の手動確認(本人の目)が残っている。

残りの負荷の内訳は E02-07 で調べた。大半はウィンドウ枚数(1枚あたり約2ポイント)で、これ以上削るのは費用対効果が低いため打ち切った。
